# 管理者モード（v1.132）

- 既存の admin_verify_business_maps を利用。パスワードはブラウザのメモリー内のみ、15分でモード終了。書き込みRPCで毎回再認証。
- public.bar_attendance_overrides は authenticated の共有閲覧のみ。直接書き込み権限は付与しない。匿名サインインによる共有閲覧は既存 business_maps と同じ要件。
- public.bar_admin_moderate は SECURITY INVOKER。非公開 bar_private.moderate が auth.uid・既存認証・Barスキーマ・元更新時刻・修正番号・フィールドを検証。
- 管理者修正は日付＋端末ID＋元personId単位。本人の再アップロードより優先。削除は非表示フラグで復元可能。元の端末データ・マップ・スケジュールは更新しない。操作履歴は非公開 bar_private.audit に保存。
- BAR_ADMIN_SETUP.sql はダッシュボードSQL Editorで適用済み。CLI/MCP管理接続が使えないため、CLI生成migrationではない。
- 検証：ロールバック付きSQLで認証・編集・競合・削除・復元・権限チェック。本番認証APIで閲覧、管理者認証、直接書込拒否、存在しない対象のRPC拒否を確認。実在の参加者の変更は残していない。
- Security Advisor：Errors 0。共有閲覧の Anonymous Sign-Ins Allowed は要件に基づく。既存認証関数などの警告は別機能のため変更しない。

# 一括アップロード（v1.131）

- マップ・スケジュール・Bar動員のアップロードは共通の確認画面を使用。Barからはマップ画面へ遷移し、全件成功後にBarへ戻る。
- このブラウザに保存されたマップ／スケジュールと、次回のBar登録を送信。Bar未登録時はスキップ表示。
- マップ／スケジュールとBarは別の保存先・匿名IDを維持。片方が失敗してももう片方を試み、結果を別々に表示。全件を単一トランザクションとして扱わない。
- Barの担当者・共有ID照合・送信履歴は既存仕様を維持。パスワードや管理者権限をクライアントに追加しない。

# Barイベント共有（v1.126）

## 保存と共有

- 入力は端末内の business_map_bar_preview_v1 に保存。試用データキーを維持。
- アップロード時のみ氏名・スポンサー・所属・区分・出欠・時間帯・来場記録を送信。備考やマップ全体は送信しない。
- 既存 business_maps テーブルを再利用。マップとは別の匿名認証ID（storageKey: business-map-bar-auth-v1）でBar専用行を保存。
- map_data.schema = bar-events-upload-v1、データは schedule_data.barEvents。既存マップとスケジュールの行は更新しない。
- 同じ端末・開催日を置き換え、他の開催日は保持。updated_at を条件にした更新で衝突時はエラーにする。
- みんなのマップ／スケジュールはBar専用行を除外する。
- 閲覧範囲は既存の共有マップと同様。担当者名は本人認証ではない。
- ブラウザデータの消去・別端末では別IDになる。旧投稿を取り戻すログイン機能はない。氏名＋スポンサーの重複候補を表示するが自動統合しない。
- 自分の過去プロスペは端末内、全体は共有済みの来場履歴から選ぶ。
- JSON保存は端末内バックアップの書き出しのみ。取り込みUIは未実装。
